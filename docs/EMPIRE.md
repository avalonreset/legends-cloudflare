# Fit the module into legends-empire

The public knowledge vault is reusable guidance. Your private Empire holds actual domains, owners, decisions, evidence and follow-up work.

1. Select your existing domain or infrastructure project. Respect its canonical path and any migration sidecar; do not create a competing task ledger.
2. Attach the versioned knowledge library (`knowledge/cloudflare/pack.json`, schema `legends.knowledge-pack/v1`) through `legends-empire` (`knowledge attach`) or link directly to `wiki/index.md`. Attachment previews first, writes into `wiki/library/legends-cloudflare/cloudflare`, and refuses to overwrite locally edited reference files.
3. Copy a template into the selected private project only when requested. Record the real observation date and link evidence stored outside managed installations.
4. Keep source observations, interpretation, decisions and outstanding verification separate. A DNS change receipt is not a registrar-transfer receipt.
5. Link one authoritative domain inventory from related projects. Do not duplicate secret-bearing API output into knowledge notes.

Templates:

- [Domain inventory](../templates/domain-inventory.md)
- [Change receipt](../templates/change-receipt.md)
- [Incident review](../templates/incident-review.md)

Plain Markdown works without Obsidian plugins or a Home installation. No automatic vault writes or paid integration is required.
